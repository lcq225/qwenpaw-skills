# wechat_publisher 风格库（v2）

> 用途：为公众号文章提供可复用的默认风格模板。每次写稿不再只“生成文章”，而是固定走：`选题判断 → 事实分层 → 结构骨架 → 正文写作 → 排版套用 → 自查复查 → 推草稿箱`。

## 共通底线

- 所有风格都服务于：**热点答疑、知识普及、帮助判断、客观公正、易读不疲劳**
- 色彩只用于区分信息类型，不用于制造噪音
- `关于本文 / 资料来源` 一律使用 **14px、浅灰、不加粗** 的低存在感 footer
- 默认不把所有模块堆满；一篇文章通常只用 2–4 种重点模块

## 风格总览

| 编号 | 风格名 | 主题键 | 适合题材 | 关键词 |
|:--|:--|:--|:--|:--|
| A | 极简科技 | `minimal_tech` | 趋势观察 / 深度分析 | 克制、耐读、留白 |
| B | 热点媒体 | `hot_media` | 今日关注 / 热点答疑 | 抓眼、轻快、可信 |
| C | 决策选型 | `decision_pick` | 横评 / 平台选择 | 对号入座、边界清楚 |
| D | 深度科普 | `deep_explain` | 原理解释 / 概念澄清 | 讲透、讲明白 |
| E | 避坑清单 | `pitfall_list` | 风险提醒 / 复盘总结 | 直接、实战 |
| F | 实操教程 | `howto` | 上手指南 / 操作步骤 | 清晰、可执行 |
| G | 争议澄清 | `clarification` | 真假辨析 / 舆论话题 | 冷静、客观 |
| H | 长文报告 | `report_longform` | 年度总结 / 行业报告 | 稳重、结构强 |
| I | 答疑服务 | `qa_service` | 公众咨询 / 误区问答 | 贴近读者、解释充分 |

## A. 极简科技

- **正文**：黑灰主导，蓝色强调少量出现
- **推荐模块**：`lead` 1 次、`point` 1 次、少量普通引用
- **禁忌**：不要铺太多色块；不要用太多 `ok/no`
- **适合标题**：趋势、判断、观察、为什么

## B. 热点媒体

- **正文**：蓝为主、黄卡辅助、橙色警示少量点缀
- **推荐模块**：`lead` + `warn` + `point`
- **禁忌**：不要为了热点而夸大结论
- **适合标题**：今天、为什么、到底发生了什么

## C. 决策选型

- **正文**：蓝关键词 + 绿/红“能/不能”对比
- **推荐模块**：`lead` + `ok/no` + `point`
- **禁忌**：不要写成参数堆砌；要先分人群再给结论
- **适合标题**：到底怎么选、适合谁、不适合谁

## D. 深度科普

- **正文**：正文占比大，蓝关键词密度略高
- **推荐模块**：`lead` + `note` + `warn` + `point`
- **禁忌**：不要为了“专业感”堆术语
- **适合标题**：到底是什么、为什么会这样、常见误解

## E. 避坑清单

- **正文**：风险色可略多，但仍需控制密度
- **推荐模块**：`warn` 为主，辅以 `tip`
- **禁忌**：不能只是列坑，要说明原因与规避办法
- **适合标题**：别再、这些坑、千万别

## F. 实操教程

- **正文**：编号步骤、段落短、注释明确
- **推荐模块**：`lead` + `tip` + `note`
- **禁忌**：少讲大理论，多讲操作顺序
- **适合标题**：怎么做、三步完成、手把手

## G. 争议澄清

- **正文**：客观中性，先列争议，再讲事实
- **推荐模块**：`lead` + `warn` + `point`
- **禁忌**：不要带情绪站队
- **适合标题**：到底是不是、被误解了、别被带偏

## H. 长文报告

- **正文**：色块最少，章节层级最强
- **推荐模块**：`lead` + `note` + 少量 `point`
- **禁忌**：不要做成 PPT 式碎片堆叠
- **适合标题**：全景、报告、复盘、年度

## I. 答疑服务

- **正文**：围绕读者真实问题展开，先给结论再展开解释
- **推荐模块**：`lead` + `note` + `point` + 少量 `warn`
- **禁忌**：不要只讲概念，不回应读者为什么会困惑
- **适合标题**：很多人都在问、到底该怎么看、常见疑问

## 快速选型口诀

- **要讲热点** → 先看 `hot_media` / `clarification`
- **要帮拍板** → 先看 `decision_pick`
- **要讲透原理** → 先看 `deep_explain`
- **要教怎么做** → 先看 `howto`
- **要讲风险** → 先看 `pitfall_list`
- **要写长文** → 先看 `minimal_tech` / `report_longform`
- **要做公众答疑** → 先看 `qa_service`
